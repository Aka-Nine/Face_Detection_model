Face Attendance Web App
1. Project Objective
The goal of the Face Attendance Web App is to create an automated attendance system that uses face recognition for employee or student identification. The system will register and log entry times when an individual is recognized by a face detection system. The application will feature both frontend and backend components working seamlessly together with machine learning models for face recognition.

2. Overall Architecture
The system is divided into three main components:

Frontend (User Interface)

Backend (API and Database Management)

Machine Learning Model (Face Recognition)

The Frontend interacts with the Backend, which processes requests (e.g., registering users or verifying attendance) and communicates with the Machine Learning Model to perform face recognition tasks.

Backend Technologies:

A modern, high-performance web framework for building APIs with Python 3.7+.

A NoSQL database used to store user records, including their unique facial embeddings, names, and attendance logs.

MongoDB's flexible schema allows easy addition of new data without restructuring the database.

MongoDB stores face embeddings as part of the user’s record and ensures efficient retrieval for matching face recognition data.

PyTorch:

An open-source deep learning framework for training and running the ResNet34 model.

It provides excellent support for neural networks and GPU acceleration, making it ideal for computer vision tasks like face recognition.

Used for running inference on the trained ResNet34 model.

OpenCV:

A powerful library for computer vision tasks.

OpenCV is used to capture frames from the webcam, detect faces in real-time, and preprocess them before feeding them into the machine learning model for inference.

4. Machine Learning Model (ResNet34)
Why ResNet34?
ResNet34 is part of the family of Residual Networks (ResNet), which are designed to solve the issue of vanishing gradients in deep neural networks by using skip connections (residual connections) that allow gradients to flow more easily during training.

ResNet34 is particularly effective for image classification tasks, making it well-suited for facial recognition where the model needs to accurately classify a person’s unique features.

The ResNet34 model uses 34 layers and is efficient in terms of computational load while maintaining high accuracy.

How It Works for Face Recognition:
Embedding Generation:

When an employee registers, their face image is passed through the ResNet34 model to generate a feature vector (embedding) that represents unique facial features.

This vector is stored in MongoDB along with other user data (e.g., name, email).

Face Matching:

During attendance verification, the webcam captures the employee’s face.

The face image is preprocessed (resized, normalized) and passed through the trained ResNet34 model.

The model generates a feature vector for the new face image.

The feature vector is compared against the embeddings stored in MongoDB. If the distance between vectors is small enough (below a predefined threshold), the faces are considered a match, and the employee’s attendance is logged.

Training the Model:

The model is trained on a large dataset of labeled faces (e.g., employees’ photos). It learns to extract distinctive features from facial images that are useful for identifying individuals.

During training, the model is optimized using a loss function such as contrastive loss or triplet loss, which helps minimize the distance between similar faces and maximize the distance between dissimilar faces.

5. System Flow
1. User Registration:
The user uploads a photo or uses the webcam to capture their face.

The face is passed through the ResNet34 model to extract an embedding.

The embedding is stored in MongoDB, along with the user’s name and other information.

A success message is shown to the user confirming that their face has been registered.

2. Attendance Verification:
The employee arrives at the office and is asked to look at the webcam for identity verification.

The system captures their face using the webcam.

The captured image is processed to detect the face using OpenCV.

The face image is passed through the ResNet34 model, which generates a new embedding.

The system compares the new embedding with the stored embeddings in MongoDB.

If a match is found (based on a threshold distance), the system logs the attendance and records the entry time in MongoDB.

3. User Dashboard:
The user can log in to the system using their credentials (email/password) or biometric login.

The dashboard displays attendance data, such as the last time they clocked in, their total hours worked, and their historical attendance.

Admin users (HR or managers) can view all employee attendance data.
